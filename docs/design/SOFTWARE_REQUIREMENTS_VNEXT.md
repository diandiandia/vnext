# Reachable Audit vNext Software Requirements

Status: as-implemented software requirements baseline, reviewed 2026-10-17 against
commit `beaef3b` plus working-tree repairs, `SOFTWARE_DESIGN_VNEXT.md`, and focused behavior checks. Existing IDs
are retained, but target-only obligations are replaced with bounded current contracts.
Evidence/status cells retain missing targets and known defects rather than declaring
them fixed. External capability acceptance is separate from implementation coverage.

## 1. Status Definitions

- **Implemented:** code and tests cover the stated requirement at the specified scope.
- **Partial:** some model or workflow exists, but a material part of the requirement is
  absent or lacks sufficient verification.
- **Not implemented:** no runtime implementation or usable asset was found.
- **Implemented, not release-certified:** the software mechanism exists, but required
  real-project, held-out, or performance evidence has not been supplied.
- **Known defect:** a reproduced behavior contradicts the intended local contract;
  documenting it does not waive the defect or certify the requirement.

Statuses refer to the bounded contract and any explicitly retained target gaps, not
an unchanged historical target specification. They are not a completion percentage.

Tests prove only the paths and inputs they exercise. Empty evidence references, booleans
in an evaluation manifest, synthetic fixtures, or a passing unit suite are not proof of
real audit capability.
