# Reachable Audit vNext Software Requirements

Status: derived from `SOFTWARE_DESIGN_VNEXT.md` and checked against the current
repository implementation and tests on 2026-10-16. This is an implementation audit,
not a claim that the target design is complete.

## 1. Status Definitions

- **Implemented:** code and tests cover the stated requirement at the specified scope.
- **Partial:** some model or workflow exists, but a material part of the requirement is
  absent or lacks sufficient verification.
- **Not implemented:** no runtime implementation or usable asset was found.
- **Implemented, not release-certified:** the software mechanism exists, but required
  real-project, held-out, or performance evidence has not been supplied.

Tests prove only the paths and inputs they exercise. Empty evidence references, booleans
in an evaluation manifest, synthetic fixtures, or a passing unit suite are not proof of
real audit capability.

## 3. Audit Summary

All 45 software requirements are traced to a software-design section and system-level
requirement. Current implementation status as of 2026-10-16 is:

| Status | Count |
|---|---:|
| Implemented | 27 |
| Partial | 14 |
| Not implemented | 0 |
| Implemented, not release-certified | 4 |

Status counts are requirement-level, not file counts. The fourteen partial requirements are
SWDR-003 (reusable, language-variant Mechanism Cards and non-templated guidance),
SWDR-007 (arbitrary unknown-language syntax), SWDR-023 (complete axis-specific
discovery protocols and non-Python hotspot providers), SWDR-028 (mechanically evidenced semantic quality review),
SWDR-031 (only the initial Python provider exists; other languages and held-out quality
evidence remain outstanding), SWDR-033 (per-Surface dispositions), SWDR-034 (general
verdict/task amendment), SWDR-035 (delegated budgets and authenticated workers), and
SWDR-036 (R5 infeasibility and authorized external evidence), SWDR-032 (path-level
scope exclusions), SWDR-039 (host-controlled prompt isolation), SWDR-040 (screening
ceiling evaluator enforcement), SWDR-041 (typed/cached evidence validation), and
SWDR-042 (bulk Handoff and empty-stage scale paths).
The four implemented but not release-certified requirements still require real held-out
language/mixed-language evidence; real 20GB+ recovery evidence is also outstanding.
