## 1. Status Definitions

- **Implemented:** code and tests cover the stated requirement at the specified scope.
- **Partial:** some model or workflow exists, but a material part of the requirement is
  absent or lacks sufficient verification.
- **Not implemented:** no runtime implementation or usable asset was found.
- **Implemented, not release-certified:** the software mechanism exists, but required
  real-project, held-out, or performance evidence has not been supplied.
- **Known defect:** a reproduced behavior contradicts the intended local contract;
  documenting it does not waive the defect or certify the requirement.

Statuses refer to the bounded contract and any explicitly retained target gaps, not
an unchanged historical target specification. They are not a completion percentage.

Tests prove only the paths and inputs they exercise. Empty evidence references, booleans
in an evaluation manifest, synthetic fixtures, or a passing unit suite are not proof of
real audit capability.

## 3. Audit Summary

All 45 IDs retain system and software-design references. This revision does not reuse
the old 27/14/4 status tally: the contracts are now explicitly bounded and a tally would
obscure retained target gaps and reproduced defects.

Working-tree repairs close the reproduced promotion-eligibility, axis-selection,
per-axis amendment, forecast aggregation, real-card R4 bundling, empty-repository,
symlink footprint, retry-abort, disconnected-chain, host-note overwrite, hotspot drift,
and missing-claim accounting defects with focused regressions. Catalog content binding
is also implemented. This does not complete the revised core contracts in software
design section 1.1. Domain parsers still lack universal strict unknown-field handling.

Remaining targets include per-path and per-Surface dispositions, review altitude,
post-commit amendment/invalidation, delegated budgets/authenticated workers, R5
NOT_FEASIBLE/external observations, reusable language variants, and full release gates.
No complete real held-out language/mixed-language or 20GB+ recovery acceptance evidence
has been supplied. A passing synthetic suite is not release certification.
